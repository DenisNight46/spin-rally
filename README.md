# Spin Rally — browser table tennis

Браузерная 3D-игра в настольный теннис: одиночный матч против ИИ и онлайн 1 × 1 через WebSocket.

## Управление

- **Мышь / палец** — положение ракетки по горизонтали и вертикали; скорость движения ракетки влияет на силу контакта, угол и вращение мяча. При приближении мяча включается слабая помощь позиционирования, чтобы уменьшить случайные промахи.
- **Клик левой кнопкой** — подача, когда наступила ваша очередь. Также доступна экранная кнопка подачи.
- **A/D или ←/→** — дополнительное перемещение ракетки влево/вправо. Глубина игрока фиксирована: вперёд-назад двигаться не нужно. Для удара перемещайте мышь коротким быстрым движением в момент контакта; движение ракетки формирует силу и вращение.
- **Esc / P** — пауза в одиночном режиме.
- **M** — звук.

Отдельных кнопок «топспин» и «подрезка» больше нет: вращение получается из фактической скорости ракетки в момент контакта. Вертикальный взмах создаёт верхнее/нижнее вращение, боковое движение — боковое вращение. Результат зависит также от входящей скорости и вращения мяча.

## Онлайн-матчи

1. Выберите «Онлайн с другом» → «Создать комнату».
2. Нажмите «Скопировать приглашение» или «Отправить другу».
3. Друг открывает ссылку — комната подключается автоматически. Можно также вручную ввести шестисимвольный код.
4. Матч начинается после подключения второго игрока.

Сервер авторитетно выполняет физическую симуляцию. Клиенты отправляют положение ракетки, а визуальное состояние мяча и ракеток сглаживается интерполяцией сетевых снимков. Комнаты временные и существуют в памяти процесса сервера.

## Техническая модель

- **Three.js / WebGL** — 3D-сцена, освещение, тени, материалы и камера.
- **Специализированная физика мяча** — собственная детерминированная симуляция, а не универсальный rigid-body preset: гравитация, квадратичное сопротивление воздуха, эффект Магнуса, угловая скорость, трение и импульсный обмен при контакте с ракеткой и столом.
- **240 Гц физический шаг** — фиксированное внутреннее время симуляции; отрисовка и сетевой обмен работают с отдельной частотой.
- **Ракетка** — импульс рассчитывается по относительной скорости мяча и ракетки, нормали поверхности и ограниченному касательному трению. Вращение не задаётся кнопкой или случайным выбором.
- **Габариты** — стол 2,74 × 1,525 м, высота 0,76 м, сетка 0,1525 м, мяч диаметром 40 мм и массой 2,7 г.
- **Онлайн** — Hono + WebSocket; сервер симулирует матч, клиент использует буфер последних снимков для плавного отображения.

Физика — инженерная игровая аппроксимация реального мяча, резины и контакта, а не лабораторно откалиброванная модель конкретной ракетки/накладки. Для точного переноса ощущений потребуются измерения реальных ударов и настройка коэффициентов по высокоскоростной съёмке.

## Запуск

```bash
npm install
npm run check
npm run build
npm start
```

Откройте `http://localhost:3000`. Для разработки — `npm run dev`.


## Публикация в интернете (ПК + iPhone/Android)

Проект включает `Dockerfile` и `render.yaml` для развёртывания как одного Node-сервиса: он отдаёт браузерную 3D-игру и обслуживает WebSocket-матчи на том же домене. Это важно: статический хостинг без WebSocket-сервера не сможет соединить двух игроков.

1. Загрузите содержимое каталога `app` в собственный GitHub-репозиторий.
2. В Render выберите **New → Blueprint**, подключите репозиторий и подтвердите `render.yaml`.
3. Дождитесь успешного Docker build и проверки `/health`.
4. Откройте выданный HTTPS-адрес на ПК и телефоне. Создайте комнату и отправьте другу приглашение из игры.

Для production лучше использовать постоянный тариф/инстанс: бесплатные инстансы могут засыпать, а комнаты пока хранятся в памяти одного процесса и сбрасываются при перезапуске или деплое. Для нескольких серверных инстансов понадобится Redis/внешний matchmaking и синхронизация комнат.

Перед публикацией выполните `npm ci`, `npm run check`, `npm test`, `npm run build`, `npm run verify`. `npm run verify` запускает браузерный smoke-test через Playwright; `npm run verify:online` проверяет создание комнаты, вход второго игрока, ping и отключение.
