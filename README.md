# Spin Rally — browser table tennis

Браузерная 3D-игра в настольный теннис: одиночный матч против ИИ, тренировка и онлайн 1 × 1 через WebSocket. Поддерживается запуск в обычном браузере и подготовлен Telegram Mini App bridge.

## Управление

- **Мышь** — наведение задаёт положение ракетки; зажмите левую кнопку и протащите курсор, чтобы выполнить удар. **Палец** — ведите по экрану: движение ракетки одновременно задаёт позицию и замах. Скорость движения влияет на силу контакта, угол и вращение мяча.
- **Подача** — когда наступила ваша очередь, выполните плавный замах ракеткой вверх. Подача запускается по движению ракетки; отдельная кнопка подачи не требуется.
- **A/D, W/S или стрелки** — перемещение ракетки по ширине и высоте. **Q/E** — приблизить ракетку к сетке / отодвинуть к себе; направление одинаково работает с обеих сторон стола.
- **Esc / P** — пауза в одиночном режиме.
- **M** — звук.

Отдельных кнопок «топспин» и «подрезка» нет: вращение формируется из фактической скорости ракетки в момент контакта. Вертикальное и боковое движение влияют на вращение; результат также зависит от входящей скорости и вращения мяча.

## Telegram Mini App

В проект добавлен клиентский мост Telegram Web Apps API. При открытии внутри Telegram игра вызывает `ready()` и `expand()`, синхронизирует высоту viewport и safe-area отступы. В обычном браузере интеграция необязательна и игра продолжает работать без Telegram SDK.

Бот проекта: **@SpinRallyGameBot**.

### Подключение Mini App

1. Сначала опубликуйте игру по HTTPS. Подойдёт один Node-сервис, который одновременно отдаёт frontend и обслуживает WebSocket.
2. Откройте официальный **@BotFather** в Telegram и выберите `/mybots` → `@SpinRallyGameBot`.
3. Откройте **Bot Settings → Configure Mini App → Enable Mini App** (названия пунктов могут немного отличаться) и укажите HTTPS URL опубликованной игры как Main Mini App.
4. При необходимости настройте **Bot Settings → Menu Button**, указав тот же HTTPS URL.
5. Откройте профиль бота и запустите Mini App. Проверьте загрузку сцены, изменение размера окна и управление пальцем.

Для первого запуска Mini App токен бота не требуется в frontend и не должен попадать в Git. Если позднее серверу понадобится Telegram Bot API, храните новый токен только в переменных окружения/секретах хостинга.

**Ограничение текущей интеграции:** клиентский мост пока отвечает за запуск и адаптацию интерфейса. Проверка подписи Telegram `initData` на сервере и доверенная идентификация Telegram-пользователя ещё не подключены. Не используйте `initDataUnsafe` как подтверждение личности и не привязывайте игровые аккаунты к непроверенным данным.

## Онлайн-матчи

1. Выберите «Онлайн с другом» → «Создать комнату».
2. Нажмите «Скопировать приглашение» или «Отправить другу».
3. Друг открывает ссылку — комната подключается автоматически. Можно также вручную ввести шестисимвольный код.
4. Матч начинается после подключения второго игрока.

Сервер авторитетно выполняет физическую симуляцию. Клиенты отправляют положение ракетки, а визуальное состояние мяча и ракеток сглаживается интерполяцией сетевых снимков. Комнаты временные и существуют в памяти процесса сервера.

## Техническая модель

- **Three.js / WebGL** — 3D-сцена, освещение, тени, материалы и камера.
- **Специализированная физика мяча** — собственная детерминированная симуляция: гравитация, квадратичное сопротивление воздуха, эффект Магнуса, угловая скорость, трение и импульсный обмен при контакте с ракеткой и столом.
- **240 Гц физический шаг** — фиксированное внутреннее время симуляции; отрисовка и сетевой обмен работают с отдельной частотой.
- **Ракетка** — импульс рассчитывается по относительной скорости мяча и ракетки, нормали поверхности и ограниченному касательному трению. Вращение не задаётся кнопкой или случайным выбором.
- **Габариты** — стол 2,74 × 1,525 м, высота 0,76 м, сетка 0,1525 м, мяч диаметром 40 мм и массой 2,7 г.
- **Онлайн** — Hono + WebSocket; сервер симулирует матч, клиент использует буфер последних снимков для плавного отображения.

Физика — инженерная игровая аппроксимация реального мяча, резины и контакта, а не лабораторно откалиброванная модель конкретной ракетки/накладки. Для точного переноса ощущений потребуются измерения реальных ударов и настройка коэффициентов по высокоскоростной съёмке.

## Запуск

```bash
npm install
npm run check
npm run build
npm start
```

Откройте `http://localhost:3000`. Для разработки — `npm run dev`.

## Публикация в интернете (ПК + iPhone/Android)

Проект включает `Dockerfile` и `render.yaml` для развёртывания как одного Node-сервиса: он отдаёт браузерную 3D-игру и обслуживает WebSocket-матчи на том же домене. Это важно: статический хостинг без WebSocket-сервера не сможет соединить двух игроков.

1. Подключите GitHub-репозиторий к Render и выберите **New → Blueprint**.
2. Подтвердите конфигурацию из `render.yaml`.
3. Дождитесь успешного Docker build и проверки `/health`.
4. Откройте выданный HTTPS-адрес на ПК и телефоне. Создайте комнату и отправьте другу приглашение из игры.
5. Используйте этот же HTTPS-адрес при настройке Main Mini App в @BotFather.

Для production лучше использовать постоянный тариф/инстанс: бесплатные инстансы могут засыпать, а комнаты пока хранятся в памяти одного процесса и сбрасываются при перезапуске или деплое. Для нескольких серверных инстансов понадобится Redis/внешний matchmaking и синхронизация комнат.

Перед публикацией выполните `npm ci`, `npm run check`, `npm test`, `npm run build`, `npm run verify`. `npm run verify` запускает браузерный smoke-test через Playwright; `npm run verify:online` проверяет создание комнаты, вход второго игрока, ping и отключение.
